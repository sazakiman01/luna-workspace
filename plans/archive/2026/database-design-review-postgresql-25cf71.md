#  Plan:  PostgreSQL Database Design Review Skill

## 1)  1-sentence summary
Create a comprehensive PostgreSQL database design review skill in Thai that helps junior developers evaluate SQL schemas against best practices across all aspects of database design.

## 2)  1-paragraph summary
This plan outlines the creation of `database-design-review-postgresql` skill that analyzes SQL files to provide detailed feedback on schema structure, performance optimization, data types, security, naming conventions, and documentation specifically tailored for junior developers learning database design, following Windsurf skill standards with Thai language support.

## 3)  3-5 bullet points of key deliverables
- **Skill Structure**: Complete directory structure with SKILL.md, README.md, assets/, and references/ following Windsurf standards
- **Review Framework**: Comprehensive PostgreSQL best practices checklist covering normalization, indexing, data types, constraints, security, and naming conventions
- **Templates**: Thai-language report templates for structured feedback with severity levels and actionable recommendations
- **Heuristics**: Database-specific evaluation criteria with examples from the PMAM schema for junior developer learning
- **Documentation**: User-friendly guides explaining database concepts and review processes in Thai

## 4)  3-5 key assumptions or constraints
- Target users are junior developers with basic SQL knowledge but limited database design experience
- Input format will be SQL files (DDL statements) similar to the PMAM schema example
- Review will focus on PostgreSQL-specific features and best practices
- All documentation and templates will be in Thai language
- Skill will provide educational explanations alongside recommendations

## 5)  3-5 key questions or concerns
- How to balance technical depth with junior developer accessibility?
- What severity levels should be used for database design issues?
- How to handle complex scenarios like denormalization for performance?
- Should the skill include automated fixes or only recommendations?
- How to structure the learning progression in the review process?

## 6)  3-5 next steps with owners
1. **Create skill directory structure** following Windsurf standards (Owner: Agent)
2. **Develop PostgreSQL best practices checklist** with Thai explanations (Owner: Agent)  
3. **Design review report template** with severity classifications (Owner: Agent)
4. **Create database heuristics** using PMAM schema as examples (Owner: Agent)
5. **Write comprehensive documentation** for junior developers (Owner: Agent)

## 7)  3-5 success criteria
- Junior developers can understand and implement the recommendations
- Reviews cover all major database design aspects comprehensively
- Templates provide actionable, educational feedback
- Skill follows Windsurf quality standards completely
- Thai documentation is clear and culturally appropriate

## 8)  3-5 risks and mitigations
- **Risk**: Technical jargon too complex for juniors | **Mitigation**: Include glossary and simple explanations
- **Risk**: Overwhelming amount of feedback | **Mitigation**: Prioritize issues by severity and impact
- **Risk**: PostgreSQL-specific features may confuse beginners | **Mitigation**: Provide context and alternative approaches
- **Risk**: Cultural/language barriers in Thai documentation | **Mitigation**: Use familiar examples and clear terminology
- **Risk**: Schema complexity variations | **Mitigation**: Handle different complexity levels with adaptive review depth

## 9)  3-5 dependencies
- PMAM database schema as reference example
- Existing Windsurf skill templates for structure guidance
- PostgreSQL documentation for best practices verification
- Thai language resources for accurate terminology
- Skill review standard for quality assurance

## 10)  3-5 timeline estimates
- **Day 1**: Create skill structure and basic templates
- **Day 2**: Develop comprehensive checklist and heuristics  
- **Day 3**: Write documentation and examples
- **Day 4**: Test with PMAM schema and refine
- **Day 5**: Final review and quality assurance
