# แผน UX/UI สำหรับหน้าคัดเลือก Auth
เอกสารนี้สรุปแนวทางออกแบบประสบการณ์เลือกระบบยืนยันตัวตน 2 ช่องทาง โดยยึดโทนมินิมอล-คลีนจากหน้า TaskList และสร้างต้นแบบที่แยกออกจากโค้ดเดิมแต่สามารถคลิกทดลองได้จริง

## 1. การค้นคว้าและข้อจำกัด
- ยกดีไซน์ไลน์จาก `src/pages/TaskList/index.tsx` (กริดการ์ด มุมโค้ง สีม่วง พื้นหลังโปร่ง และข้อความภาษาไทย) โดยไม่แก้ไฟล์เดิม
- เก็บโจทย์ UX: เน้นว่า Amazon Cognito เป็นเส้นทางแนะนำ แต่ยังคงให้เลือก EkoApp ได้ พร้อมอธิบายบริบท "กำลังเปลี่ยนถ่ายระบบ"
- ระบุพฤติกรรมที่ต้องมี: ตัวเลือกคลิกได้, เอฟเฟกต์ hover/focus, คำอธิบายสั้น/tooltip ของแต่ละระบบ, และการให้ feedback เมื่อเลือกเสร็จเพื่อพาผู้ใช้ต่อไป

## 2. ร่าง UX และคอนเทนต์
- ผังการใช้งาน: เปิดด้วย hero บอกสถานะการเปลี่ยนระบบ → การ์ดเลือก 2 ช่องทาง → modal/toast บอกขั้นตอนถัดไป (รวมกรณี fail เช่น network มีปัญหาหรือเบราว์เซอร์ไม่รองรับ EkoApp)
- อธิบายระดับ wireframe (โครง section, การจัด component, การตอบสนองบน mobile) พร้อม microcopy สำหรับหัวเรื่อง ปุ่ม CTA ข้อความช่วยเหลือ และข้อความกระตุ้นให้ย้ายไป Cognito
- ชี้ accessibility ที่ต้องคำนึง: เดินด้วยคีย์บอร์ดได้, เส้น focus ชัด, label สำหรับ screen reader และระบุ event สำหรับเก็บ analytics ตอนผู้ใช้เลือกช่องทาง

## 3. กลยุทธ์ทำต้นแบบแบบโต้ตอบ
- สร้างหน้าแยก (เช่น `/auth-selector-demo`) โดยใช้ component ใหม่ทั้งหมด แล้วผูก route/entry เฉพาะเพื่อเดโมโดยไม่แตะหน้าปัจจุบัน
- อธิบายการจัดการสถานะ: มี state machine เล็ก ๆ บอกสถานะการเลือก, จำลอง async call ไปหา UI ของแต่ละ auth และมี dialog mock ให้เห็นว่าจะเกิดอะไรหลังเลือก Cognito/EkoApp
- กำหนดแนวทางธีม: สร้าง utility class ให้สอดคล้องกับโทน TaskList, ใช้อนิเมชันเบา ๆ (การ์ดขยาย/แจ้งความสำเร็จ) และทำข้อมูลเป็น config เพื่อให้ทีมดีไซน์ปรับข้อความ/ไอคอนได้ง่าย
